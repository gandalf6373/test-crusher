# 🚀 test-crusher

> 把开发功能点列表，直接变成可审核的测试用例 Excel。

![test-crusher banner](./docs/assets/test-crusher-banner.svg)

还在手动拆测试步骤、补异常场景、统一表格格式？  
`test-crusher` 的目标很直接：**让 QA 从“整理表格”回到“判断质量”。**

## ⚡ 一眼看懂它能帮你什么

- 把 Markdown / Excel 开发点列表直接转换成测试用例 Excel
- 默认补齐正向、异常、边界这几类常见测试场景
- 统一输出格式，方便审核、交接、执行
- 输入不完整时，不会乱编，而是先告诉你缺什么

## 😵 你现在可能还在这样做

### 手工模式

1. 先看研发拆解
2. 再自己补页面步骤
3. 再自己补异常和边界
4. 再整理成 Excel
5. 最后还要自己检查有没有漏

### `test-crusher` 模式

1. 贴开发功能点
2. 直接生成标准化测试用例 Excel
3. 信息不足时先收到缺失项清单
4. 审核后直接交给执行工具

## 📈 使用前后变化

| 场景 | 之前 | 现在 |
|------|------|------|
| 50 个开发点整理成测试用例 | 手动写 3-5 小时 | **几十秒产出初稿** |
| 异常和边界场景补充 | 靠经验，容易漏 | **自动补齐常见覆盖项** |
| 用例格式 | 每个人风格不同 | **统一成同一套 Excel 结构** |
| 输入不完整时 | 硬着头皮继续写 | **先提示缺失项，再决定是否生成** |

## 🎯 它最适合什么场景

- 你已经有整理好的开发功能点列表
- 你要快速产出测试用例初稿
- 你想统一团队测试用例结构
- 你希望把时间花在测试判断，而不是表格搬运

## 📦 最终会拿到什么

你最终拿到的是一个**可审核的测试用例 Excel**，默认采用页面操作视角。

常见字段包括：

| 字段 | 说明 |
|------|------|
| 用例编号 | `模块简称-001` |
| 模块 | 功能模块 |
| 用例标题 | 简洁测试目标 |
| 优先级 | P0 / P1 / P2 |
| 用例类型 | 功能 / 页面 / 边界 / 异常 |
| 前置条件 | 执行前准备 |
| 执行路径 | 页面入口或功能入口 |
| 输入数据 | 页面输入数据或可见测试数据 |
| 操作步骤 | 点击、输入、提交、校验 |
| 预期结果 | 页面提示、状态变化、列表结果 |
| 执行方式 | 手动 / 自动化 |
| 是否可自动化 | 是 / 否 / 待定 |
| 备注 | 推断项、限制项、待确认项 |

## 🛠 默认会帮你补哪些测试场景

除非你明确缩减范围，否则会尽量覆盖：

- 正常流程
- 必填校验
- 格式校验
- 长度或边界值
- 唯一性校验
- 异常提示
- 状态流转
- 关联对象存在性或有效性
- 重复提交
- 列表结果可见性

## 🚀 三步上手

### 1. 给它开发点

你可以贴 Markdown，也可以上传 Excel。

```text
帮我生成测试用例，这是研发任务拆解：

## 系统：管理后台
### 模块：设备管理
- [后端] 设备新增接口（device_no 唯一校验）
- [前端] 新增设备表单页（字段校验 / 提交提示）
- [测试] 正常新增 / 编号重复拦截
```

### 2. 它先判断能不能直接生成

`test-crusher` 不会拿到任何输入就直接输出表格。  
它会先看三件事：

- 有没有明确模块
- 有没有明确开发点主体
- 能不能映射出页面动作或可见业务结果

### 3. 输出结果

- 信息完整：直接生成可审核 Excel
- 信息不足：先返回缺失项清单，不强行生成

## 🧠 为什么这比“直接生成”更稳

很多工具的问题不是“生成得慢”，而是“明明信息不够，还硬生成一份看起来完整的表”。

`test-crusher` 的规则是：

- 不输出 API 路径
- 不直接写接口请求参数
- 重点落到页面入口、页面动作、可见结果
- 无法确认的内容标成 `待确认`
- 由后端描述推断出的内容，必须在备注中标明

这能显著减少“表格有了，但实际上没法测”的情况。

## 📥 安装

### Windows PowerShell

```powershell
git clone <your-repo-url>
Set-Location test-crusher
New-Item -ItemType Directory -Force "$HOME\.codex\skills" | Out-Null
Copy-Item -Recurse -Force ".\*" "$HOME\.codex\skills\test-crusher"
```

### macOS / Linux

```bash
git clone <your-repo-url>
cd test-crusher
mkdir -p ~/.codex/skills
ln -sfn "$(pwd)" ~/.codex/skills/test-crusher
```

安装后重启 AI 工具。

## ✅ 生效后的表现

如果 skill 已正确生效，模型应该会这样工作：

- 输入完整：直接生成可审核 Excel
- 输入不足：先指出缺失项，不强行生成
- 输出内容：以页面操作和可见结果为主，不乱写接口细节
